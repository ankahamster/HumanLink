# 项目技术栈定位/原则与优化方向

# 技术栈核心定位/原则

Humanlink 不重在构建一个封闭的单一硬件安全系统，重在设计开放协议层，定义面向 AI 高风险操作的**人类在场授权证明**。HumanLink 的工程路线是**通过开放接口、模块化硬件和统一验证协议，实现可验证、可审计、可扩展的人类授权基础设施。**

- **协议优先，硬件作为可信执行载体**
    - HumanLink 重在构建面向 AI Agent 高风险操作的开放式人类在场授权协议，而不是单一硬件产品。
    - 协议层负责定义 `Challenge`、`actionHash`、`HumanPresenceAssertion`、设备身份、签名格式、验证流程和审计接口。
    - 硬件负责执行人类在场验证、保护不可导出私钥，并对与具体操作绑定的授权上下文进行签名。
- **开放接入，基于分立式硬件架构的HAI抽象接口**
    - 当前 `ESP32 + JM-101 + ATECC608A` 是 HumanLink HAI 的参考实现；其分立式组合将人类在场验证、策略控制和硬件签名拆分为可替换模块。
    - HAI 不绑定特定硬件型号，重在定义合规 HumanLink Issuer 即Assertion 签发设备必须具备的能力和输出格式。
        - **硬件开放：**硬件可以升级或替换，但授权 assertion 的数据结构、签名语义和验证逻辑应保持兼容。
        - **接入开放：**不同接入方，如 Agent harness、AI Gateway、企业平台或本地应用等，可以通过统一 SDK调用 HumanLink 授权层，不需绑定特定Agent平台或部署形态。
        - **验证开放：**不同 verifier 可以基于公开的 assertion 格式、设备身份、签名规则和验证流程独立验签，而不依赖单一平台自证。
        - **审计开放：**不同审计系统可以检查授权记录、设备状态、撤销状态和操作绑定关系，实现跨平台的授权追溯与争议举证。
- **安全原则参考封闭硬件系统，工程路线不依赖封闭生态**
    - 封闭硬件系统通常具有更集中的安全边界和更强的一体化安全能力。
    - HumanLink **不重在复刻封闭硬件生态，而是参考其关键安全机制：**硬件根信任（外设、链路、固件、签名可信）、私钥不可导出、可信确认（用户确认内容与最终签名执行内容一致）、上下文绑定签名和防重放。

# 硬件架构优化方向

| 方向 | 当前基础 | 待增强点 |
| --- | --- | --- |
| ESP32 自身可信 | ESP32 负责接收 `H_doc`、调度 JM-101 和 ATECC608A，并返回硬件签名 | 开启 Secure Boot、Flash Encryption、Anti-rollback，防止恶意固件绕过指纹/活体流程并直接触发 ATECC608A 签名 |
| 外设模块可信 | JM-101 负责指纹采集和本地模板匹配，返回 `matched_id`、`score` 和芯片序列号；Assertion 层已有 `score` 和 `sensor_Serial` | JM-101 缺少模块级公私钥、模块证书和强 attestation；后续应引入带模块证书、不可导出私钥和签名输出能力的活体模块，或在模块侧增加 Secure Element，防止认证外设模块替换 |
| 模块链路可信 | 当前链路为 JM-101 与 ESP32 之间 UART、ESP32 与 ATECC608A 之间 I2C、主机与设备之间 USB Serial | 对关键通信加入 nonce、counter、MAC 或加密通道，保护 Challenge 哈希、认证结果、签名请求和模块状态，防止监听、重放、注入和模块替换 |
| 授权证据与审计可信 | 已设计 `HumanPresenceAssertion` 结构，其中 `challenge` 字段包含 `actionHash`、`requiredIssuerDID`、`nonce` 和 `origin`；`proof` 字段包含 ECDSA签名。`H_doc` 和 `H_final` 是签名生成流程中的中间哈希，用于将 assertion 骨架、指纹匹配结果和传感器序列号绑定到最终签名。 | 把模块证书、活体结果签名、ESP32 固件状态、设备端确认状态纳入授权证据体系，使 verifier 可检查设备、模块、固件和 assertion 状态 |
| 用户确认可信 | `display`**由验证方填写**。用户在 HumanLink 设备上看到的操作摘要来自承担责任的验证方，不来自 Agent 本身。已有 `challenge.display.title`、`challenge.display.summary`、`challenge.display.risk`、`challenge.display.source` 。 | 增加设备端可信显示、按钮确认或短 hash 校验，保证用户看到的操作内容与最终签名绑定的 `actionHash` 一致 |
| 活体能力可信 | 当前 JM-101 更接近指纹匹配触发，对伪造等攻击抵抗不足，不是强认证活体模块。 | 升级为具备本地活体判断、防伪造能力、模块证书、签名输出和安全密钥存储的生物认证模组 |
